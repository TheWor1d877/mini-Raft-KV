# 项目总体要求


## 交付物

| 产出 | 内容 | 落点 |
|:---|:---|:---|
| 设计取舍 | 每个决定记清当时的约束、被否掉的方案和代价 | `docs/`、issue |
| 踩过的坑 | 每个值得讲的问题开一条 GitHub issue：现象、根因、改法 | GitHub issues |
| 数据与对照表 | 故障注入结果、与 etcd 的行为对拍结果 | `docs/`、实验记录 |
| 复盘笔记 | 项目结束后整理成能反复讲的版本 | `/home/howardhe/Project/Note/mini-Raft KV/` |

## 硬性约束

- 每个取舍都要能说出「为什么不选另一个」，只写「选了 X」不算产出。
- 坑必须来自真实运行与真实故障，不做纯笔记层面的推演。
- 数据必须有对照：没有 baseline 的数字不进结论。
