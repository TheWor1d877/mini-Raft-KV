# 2.2 单机 KV + WAL 测试说明

## 1. 文档说明

测试范围：`2.1` 描述的 kv／wal／record／recovery／dir／log 六个内部件，加上 `cmd/miniraft-kv` 的进程入口。日志压缩与快照不在范围内（D7），etcd 对拍（T14）也不在这份文档里，它产出的是数据表，不是断言。

分层：

| 层 | 跑法 | 特点 |
|:---|:---|:---|
| 单元 | `go test`，纯内存或 `t.TempDir()` 临时目录 | 不依赖进程，秒级 |
| 集成 | 同一包内跨件调用（wal + recovery + kv） | 真文件、真 fsync |
| 进程级 | 测试自己 `exec` 起 `cmd/miniraft-kv` 子进程，发请求、`kill -9`、重启对账 | 慢，只在回归和注入实验里跑 |
| 契约 | HTTP 请求与响应字段断言 | 覆盖错误码到状态码的映射 |

环境与依赖：Linux 本地盘（`t.TempDir()` 所在文件系统），Go 1.22 以上，第三方依赖只有 `go.uber.org/zap`，日志断言用 `go.uber.org/zap/zaptest/observer`。`go test ./...` 全程不依赖 docker、不依赖 etcd；T14 的 etcd 5 节点起法见 D11，走脚本，与测试套件分开。跨机挂载（NFS 等）与容器卷按 D8 划在范围外。

怎么读覆盖结论：`5` 里的「已覆盖／部分覆盖／缺失」按 `2.4` 的覆盖判断同步维护，一格写缺失就是没跑过，别用「CI 绿了」代替它。

## 3. 逐文件说明

| 文件 | 被测对象 | 关键断言 | 覆盖场景 |
|:---|:---|:---|:---|
| `record_test.go` | `record.Encode/Decode`、crc 计算（T6） | 逐字节等于 `2.1` §5 的字段表（`Put("k1","hello")` → entry 16B、记录 24B）；`len` 的 32 个 bit 逐个翻转全部判坏；entry 内翻位同样判坏；crc 与只盖 entry、只盖 `len` 两种算法都不相等；`op` 非 `0x01` 判坏记录；`keylen`/`vallen` 与 entry 实际字节数不符（crc 自算）判坏记录；坏记录错误一律带 `offset`；key 超 1KB、value 超 1MB 返回 `ErrTooLarge` 且不产生任何字节 | 正常、边界（`len`=0、上限 4MB、超限）、损坏 |
| `wal_append_test.go` | `wal.Append`（T7） | 连续追加 1000 条后重开文件能按序读回；追加失败不产生半条记录；追加序等于调用返回序 | 正常、IO 错 |
| `wal_sync_test.go` | 批次 Sync（T7、D6） | 第 64 条前后各发生一次 Sync；未满 64 条时 `Flush()` 立即 Sync；批次计数在 Sync 后归零；`Close()` 前未满批次被落盘；每次 Sync 覆盖的偏移等于文件末尾；`-fsync=false` 时批次照常归零但不调 Sync（把 fd 换成管道，真调用必 EINVAL） | 正常、边界（恰好整批、Close 带残留、关掉 Sync） |
| `dir_lock_test.go` | `dir` 的 flock（T8） | 第二个 `Open` 返回 `ErrLocked`；`Close` 后能再开；进程被杀后重启能拿到锁 | 正常、异常 |
| `rollover_test.go` | 100MB 滚动（T9，测试里把阈值调小） | 越过阈值换新文件、序号递增；老文件不被删、不被改写（D7）；恢复只靠文件名排序，12 个文件下顺序正确；残留 `*.tmp` 被忽略并删除；恢复结果等于全部历史重放 | 正常、边界、崩溃遗留 |
| `recovery_test.go` | 扫描与重放（T10） | 全部记录重放后 map 等于写入终态；空目录、只有空文件、多文件三种输入都能起；恢复只打一条汇总日志不逐条打 | 正常、边界 |
| `truncate_test.go` | 坏尾裁剪（T10） | 五种坏记录各一例：截半（含剩余不足 8B）、`len` 越界、读不满 entry、crc 不符、`op` 非法；断言 `Truncate` 到坏尾起点；重启第二次不再重复截；断言「写入条数 = 恢复条数 + 丢弃条数」；日志里 `offset` 与实际字节位置一致 | 损坏、重复执行 |
| `kv_test.go` | `Open/Put/Get/Flush/Close`（T11、D4） | key 不存在返回 `ErrKeyNotFound` 且 `errors.Is` 成立；空串 key、空串 value 能写能读，与「不存在」可区分，重启后仍可区分；同 key 重放十次再改值再重放十次，终态与一次相同、盘上留下全部 21 条；`Put` 追加失败后 `Get` 读不到该值且重启也读不到；key 超 1KB、value 超 1MB 返回 `ErrTooLarge` 且盘上零记录，恰好上限能写进；`Close` 落掉未满的一批并释放目录锁；`Open` 撞锁返回 `ErrLocked` 且不会放掉持有者的锁；成功与失败的 Put 日志都带 `req_id`，超限拒绝不打写失败日志 | 正常、边界、幂等、异常 |
| `kv_concurrency_test.go` | 读写锁（T11） | `-race` 下 8 写 8 读跑 1 秒无竞态；成功写数等于 WAL 记录数；Get 读到的每个值都属于某次已返回成功的 Put；map 终态等于按序重放 WAL；重启后再对账一次；另有一组 4 写 × 50 条、段上限压到 64B 的用例，断言段号连续非空、盘上没有未被确认的记录 | 并发、数据对账、并发换段 |
| `fsync_fail_test.go` | fail-stop 的判据（T17、D5） | fd 换成管道（Write 成功、Sync 必 EINVAL）：第 64 条 Put 返回 `ErrIO` 并带 errno、失效标志置位、失效日志只有一条、后续 Put 全失败且不再走追加、`Flush` 也返回 `ErrIO`、`Get` 仍读到已确认的 63 条、`Close` 不产生第二次失败日志、重启后读到的等于盘上真有的；`chmod 0555` 让建新段失败：Put 返回 `ErrIO` 但失效标志不置位、被拒的值不进 map、权限恢复后继续可写且已确认记录一条不少；失效标志不跨重启 | 异常、故障恢复、失效判据 |
| `config_test.go` | `config`（T5、D8） | 缺省值等于 `2.1` §6 与 §8；命令行覆盖生效；非法值（负批次、空目录）报错不静默改默认 | 正常、边界、异常 |
| `errors_test.go` | 哨兵错误与包装（T3） | `errors.Is` 能穿透两层 `fmt.Errorf(%w)`；`ErrCorruptRecord` 的包装里带 `offset`；`ErrIO`、`ErrLocked` 的包装里保留原始错误，`errors.As` 取到 `syscall.Errno` | 契约 |
| `logging_test.go` | 日志封装（T15） | 通用字段 `ts/level/msg/component` 齐全；字段名全小写下划线；`ts` 是 UTC RFC3339；value 不出现在任何日志行，只出现 `value_len` 与指纹前 8 位；`req_id` 在入口到 kv 的调用里保持不变 | 契约、脱敏 |
| `http_api_test.go` | HTTP 入口（T12、D10） | `POST /put`、`GET /get` 正常返回，空串 key 与空串 value 也能存取；404 带 `code=key_not_found`、413 带 `code=too_large`、写路径关掉后 500 带 `code=io_error` 且读仍可用；错误类别到状态码的映射表逐条断言，含坏记录的 `offset` 能被取出；非法 JSON、空体、数组、一个请求体塞两个对象全是 400 且不改动已有状态；请求体超 4MB 是 413，且不进写路径（没有 `put rejected` 日志）；永不收尾的超限流同样 413，且服务端实际读走的字节被上限卡住（去掉体大小上限就会读满整份请求）；方法与路由守卫 405/404；64 个并发请求的 `req_id` 互不重复并且和 kv 日志里的一致；4xx/5xx 与成功两类日志的字段齐全、全小写下划线、不带 value；写路径失效只通知入口一次 | 契约、异常、并发 |
| `crash_restart_test.go` | 进程级崩溃（T13、D5、D6、D13） | 测试自己 `go build` 出 `cmd/miniraft-kv` 再起子进程，发真 HTTP 请求：批次未满时 `kill -9`，恢复条数落在 `[acked-63, acked]` 区间，读回的值必须等于写进去的值；段上限压到 512B 后写 400 条再被杀，恢复的段数 ≥2 且没有 `*.tmp` 残留；预先放一个高一号的未提交临时段，重启必须删掉它、已提交段一条不少、段号不跳号；`chmod 0555` 挡住建新段时进程只回 500、读仍服务、不自杀、权限恢复后继续写；SIGTERM 收尾后 100 条一条不丢、退出码 0、LOCK 文件仍在；地址被占时进程自己退出、码为 1、原因同时写 stderr 与日志、留下 `wal closed` 且同一目录随后能再起 | 故障注入、进程入口 |
| `longrun_test.go` | 长时间运行（T18） | 无断言；输出「记录条数—磁盘占用—重启耗时」三列数据表 | 长跑 |
| `cmd/miniraft-kv`（进程入口） | 配置加载、起停、优雅关闭、失效退出（T12、T13、D5） | 由 `crash_restart_test.go` 起真子进程覆盖：SIGTERM 退出码 0 且不丢数据，写路径没关掉时不因 500 而自杀，被杀时残留的未提交段在重启前被清掉；配置非法由 `config_test.go` 覆盖；地址被占时进程自己退出、码为 1、原因同时落日志与 stderr，且失败路径放掉目录锁（同目录随后能再起） | 进程入口 |

## 5. 覆盖缺口与补充计划

| 区域 | 判断 | 优先级 | 补充 |
|:---|:---|:---|:---|
| 帧编解码与 crc | 已覆盖 | — | — |
| 追加、批次 Sync、滚动 | 已覆盖 | — | — |
| 恢复与坏尾 | 已覆盖 | — | 坏尾之后仍有正常记录的人为构造已钉住：策略是连同其后全部丢弃，见 `truncate_test.go`（`2.4` 覆盖判断同条） |
| 并发 | 已覆盖 | — | 长跑 1 秒版本已进 `kv_concurrency_test.go`；更长的留给 T18 |
| 崩溃时机 | 已覆盖 | — | 批次中途被杀、滚动途中被杀、未提交临时段残留三种都在 `crash_restart_test.go`；`fsync` 系统调用真失败（磁盘满）造不出来，追加失败用只读 fd、Sync 失败用管道代替，记录在 D5 的影响里 |
| 入口的失效退出（退出码 1） | 部分覆盖 | 低 | 外部造不出真 fsync 失败：`kill -9` 之后页缓存还在，磁盘满也模拟不了。「只通知入口一次」由 `TestHTTPNotifiesShutdownOnceOnDisabledWrites` 钉住，`main.go` 里收到通知→收尾→退出码 1 这段与 SIGTERM 共用同一条路径，由 `TestGracefulShutdownLosesNothing` 覆盖到退出码 0 那一半；退出码 1 的另一条来源（地址被占）由 `TestProcessExitsWhenAddressIsTaken` 钉住 |
| 目录锁跨文件系统 | 不适用 | — | 按 D8 划在范围外，本地盘与 bind mount 语义已够 |
| HTTP 边界 | 已覆盖 | — | 64 个并发请求的 `req_id` 唯一性、以及响应里的 `req_id` 与 kv 写日志一致，两条断言在 `http_api_test.go` |
| 压缩与快照 | 不适用 | — | 本期不做（D7），不进矩阵 |
| 已有模块回归 | 不适用 | — | 本模块是仓库第一个模块；从 M3 起每次合并跑全量 `go test -race ./...`，防新代码改坏旧用例 |
