# 2.2 单机 KV + WAL 测试说明

## 1. 文档说明

测试范围：`2.1` 描述的 kv／record／dir／log／config 五个内部件，加上 `cmd/miniraft-kv` 的进程入口。日志本身（追加、Sync、段滚动、坏尾裁剪、恢复扫描、截断）已经并进 `internal/raft`，它的用例在 `3.2`；`docs/5` 的压缩与快照、etcd 对拍（T14）也不在本文件范围内，后者产出数据表。

分层：

| 层 | 跑法 | 特点 |
|:---|:---|:---|
| 单元 | `go test`，纯内存或 `t.TempDir()` 临时目录 | 不依赖进程，秒级 |
| 集成 | 同一包内跨件调用（kv + dir + config） | 真文件、真 flock |
| 进程级 | 测试自己 `go build` 出 `cmd/miniraft-kv` 起子进程，发真 HTTP 请求、`kill -9`、重启对账 | 慢，只在回归和注入实验里跑；子进程的日志只落 `<data-dir>/log/miniraft-node.log`、不落 stdout，所以失败断言要读该日志文件的末尾，否则打印出来的输出恒为空 |
| 契约 | HTTP 请求与响应字段断言 | 覆盖错误码到状态码的映射，用例在 `internal/raft/http_rpc_test.go` |

环境与依赖：Linux 本地盘（`t.TempDir()` 所在文件系统），Go 1.22 以上，第三方依赖只有 `go.uber.org/zap`，日志断言用 `go.uber.org/zap/zaptest/observer`。`go test ./...` 全程不依赖 docker、不依赖 etcd；T14 的 etcd 5 节点起法见 D11，走脚本，与测试套件分开。跨机挂载（NFS 等）与容器卷按 D8 划在范围外。

覆盖结论：「已覆盖／部分覆盖／缺失」按 §5 的表逐格同步维护，一格写缺失就是没跑过；CI 通过不能替代该判断。

## 2. 运行命令

工作目录 `/home/howardhe/Project/mini-Raft`。

| 用途 | 命令 | 前置 |
|:---|:---|:---|
| 构建 | `go build ./...` | — |
| 全量单测与集成 | `go test ./...` | — |
| 并发与竞态 | `go test -race ./...` | 每个里程碑合并前必跑 |
| 静态检查 | `go vet ./...` | — |
| 只跑崩溃恢复 | `go test -run 'Crash\|Recover\|Rebuild\|Truncate' ./internal/kvstore ./internal/raft` | 无 |
| 进程级注入 | `scripts/crash_inject.sh 2000 1500` | 先 `go build -o bin/miniraft-kv ./cmd/miniraft-kv`；参数依次是写入条数、第几条之后 `kill -9`、`-raft-fsync`（true／false）、段上限；`KEEP=1` 保留数据目录；产出一行 `fsync acked durable not_durable recovered lost boot_ms segments stale_tmp`，第一格装的是 `-raft-fsync` 的取值，`durable` 取重启后日志里的 `replayed_entries` 加上其后 `component=kv` 的 `entry applied` 条数 |
| 回归 | `go vet ./... && go test -race ./...` | M8、T16 |
| CI | 上面四条静态检查与全量 | M0、T2 |

进程级测试默认不进 CI 的短时任务，用 `-short` 跳过：`go test -short ./...`。

单节点集群起来先停在 Follower，等满一个选举截止（`[T,2T)` = 500~1000ms）才自票当选（`3.1` §7），所以第一条客户端写落在日志 index 2，index 1 是当选那轮的 no-op。进程级用例与注入脚本都按这个偏移取数。

## 3. 逐文件说明

| 文件 | 被测对象 | 关键断言 | 覆盖场景 |
|:---|:---|:---|:---|
| `record_test.go` | `record.Encode/Decode`、crc 计算（T6） | 逐字节等于 `2.1` §5 的字段表（`Put("k1","hello")` → command 16B、含日志头一帧 41B）；`len` 的 32 个 bit 逐个翻转全部判坏；command 内翻位同样判坏；crc 与只盖 command、只盖 `len` 两种算法都不相等；command 的 `op` 非 `0x01` 判坏记录；`keylen`/`vallen` 与实际字节数不符判坏记录；坏记录错误一律带 `offset`；key 超 1KB、value 超 1MB 返回 `ErrTooLarge` 且不产生任何字节 | 正常、边界（`len`=0、上限 4MB、超限）、损坏 |
| `dir_lock_test.go` | `dir` 的 flock（T8） | 第二个 `Open` 返回 `ErrLocked`；`Close` 后能再开；进程被杀后重启能拿到锁 | 正常、异常 |
| `kv_test.go` | `Open/Apply/Get/Close`（T11、D4） | key 不存在返回 `ErrKeyNotFound` 且 `errors.Is` 成立；空串 key、空串 value 能存取，与「不存在」可区分；同一条重复 apply 终态不变；`Apply` 打一条 `component=kv` 的 `entry applied`，只带 `value_len` 与指纹；`req_id` 从 `WithRequestID` 进、`RequestID` 出；`Close` 释放目录锁、同一目录随后能再起；`Open` 撞锁返回 `ErrLocked` 且不会放掉持有者的锁；配置非法（空目录、非正段上限）在 `Open` 里报错 | 正常、边界、幂等、异常 |
| `kv_concurrency_test.go` | 读写锁（T11） | `-race` 下 8 写 8 读跑 1 秒无竞态；读到的每个值都属于某次已发生的 `Apply`；map 终态覆盖所有写过的 key，每个值也都属于某次 `Apply` | 并发、数据对账 |
| `config_test.go` | `config`（T5、D8） | 缺省值等于 `2.1` §6 与 §8；`DefaultDataDir`／`DefaultMaxFileSize`／`DefaultLogLevel` 只有这一处定义，命令行与 raft 侧都从这里取；命令行覆盖生效；非法值（空目录、非正段上限、认不出的日志级别）报错不静默改默认 | 正常、边界、异常 |
| `errors_test.go` | 哨兵错误与包装（T3） | `errors.Is` 能穿透两层 `fmt.Errorf(%w)`；`ErrCorruptRecord` 的包装里带 `offset`；`ErrIO`、`ErrLocked` 的包装里保留原始错误，`errors.As` 取到 `syscall.Errno`；`ErrTooLarge` 带 size 与 limit | 契约 |
| `logging_test.go` | 日志封装（T15） | 通用字段 `ts/level/msg/component` 齐全；字段名全小写下划线；`ts` 是 UTC RFC3339；value 不出现在任何日志行，只出现 `value_len` 与指纹前 8 位；`component` 取值只有 `wal`／`kv`／`entry`，形状用例打的是 `wal` 的 `wal rolled over`（带 `from_file`/`to_file`/`size_bytes`）与 `corrupt record tail`；`req_id` 在入口到状态机的调用里保持不变 | 契约、脱敏 |
| `crash_restart_test.go` | 进程级崩溃（T13、D5、D13） | 测试自己 `go build` 出 `cmd/miniraft-kv` 再起子进程，发真 HTTP 请求：写完一批后 `kill -9`，确认过的条数在重启后一条不少，且日志 index 连续、第一条写落在 2（1 是当选 no-op）；顶层没有 `wal/`、`raft/wal/` 有段、`raft/state` 的 `lastApplied` 不小于确认条数；SIGTERM 收尾后 100 条一条不丢、退出码 0、LOCK 文件仍在，入口行是 `component=entry` 的 `node started`／`node stopped`；收尾时在场一条只连不说话的裸连接，进程仍是退出码 0 且收尾耗时 <4 秒（`TestSilentConnectionDoesNotBlockShutdown`，去掉入口主动关沉默连接那一步就会撞满 5 秒窗口退 1）；`chmod 0555` 挡住建新段时进程只回 500、读仍服务、不自杀、权限恢复后继续写；地址被占时进程自己退出、码为 1、原因同时写 stderr 与日志、放掉目录锁且同一目录随后能再起 | 故障注入、进程入口 |

`fsync` 失败、坏尾裁剪、段滚动与恢复扫描的用例不再在本包：D5 的失效判据由 `internal/raft/wal_test.go` 的 `TestRaftLogSyncFailureDisablesWritesOnly` 与 `internal/raft/http_rpc_test.go` 的 `TestRaftLogSyncFailureClosesTheWritePath` 钉住，坏尾与滚动由 `internal/raft/wal_test.go` 钉住，回放重建 map 由 `internal/raft/recovery_test.go` 钉住，对应格子见 `3.2` §3。

## 5. 覆盖缺口与补充计划

| 区域 | 判断 | 优先级 | 补充 |
|:---|:---|:---|:---|
| 帧编解码与 crc | 已覆盖 | — | — |
| 追加、Sync、滚动、坏尾 | 已覆盖 | — | 用例落在 `internal/raft`（`3.2` §3 的 `wal_test.go`），本包不再有一份 |
| 恢复与 map 重建 | 已覆盖 | — | 回放重建与「解不出就启动期失败」两格在 `internal/raft/recovery_test.go` |
| 并发 | 已覆盖 | — | 长跑 1 秒版本已进 `kv_concurrency_test.go`；`-race` 下必跑 |
| 崩溃时机 | 已覆盖 | — | `kill -9` 之后重启对账、建新段被权限挡住、地址被占三种在 `crash_restart_test.go`；`fsync` 系统调用真失败（磁盘满）造不出来，Sync 失败用管道代替，记录在 D5 的影响里 |
| 长跑与重启耗时的增长曲线（T18） | 部分覆盖 | 低 | 没有 `longrun_test.go`，自动化长跑这一格仍未落。曲线要回答的问题已由 `scripts/bench_snapshot.sh`（T35）答了：5000 条无快照全量回放 68.9~73.3ms，快照点落在日志末尾时 14.1~14.9ms，读数与口径在 `docs/0` M16 那一节。`crash_inject.sh` 的 `boot_ms` 量的是恢复链路，快照在场时它不再等于全量回放（`5.1` §9） |
| 入口的失效退出（退出码 1） | 部分覆盖 | 低 | 外部造不出真 fsync 失败：`kill -9` 之后页缓存还在，磁盘满也模拟不了。「只通知入口一次」由 `internal/raft/http_rpc_test.go` 钉住，`nodeapp.Run` 里收到通知→收尾→退出码 1 这段与 SIGTERM 共用同一条路径，退出码 0 那一半由 `TestGracefulShutdownLosesNothing` 覆盖；「收尾出错也退 1」由 `TestSilentConnectionDoesNotBlockShutdown` 钉住另一面；退出码 1 的另一条来源（地址被占）由 `TestProcessExitsWhenAddressIsTaken` 钉住 |
| 收尾窗口等的是谁 | 已覆盖 | — | 在途请求与空闲 keep-alive 由 `TestGracefulShutdownLosesNothing` 覆盖（客户端发完 100 条后连接留在池里，`Shutdown` 自己关）；只连不说话的沉默连接由 `TestSilentConnectionDoesNotBlockShutdown` 覆盖，判据是退出码 0 加收尾耗时 <4 秒，两个数缺一不可：只看退出码时把窗口调大也能过。入口那条 `closed connections that never sent a request` 日志只断存在性、不断条数：一次收尾时留在 `StateNew` 的连接数由本用例自己的客户端决定，3 并发 `-race` 下 1 和 2 都出现过 |
| 目录锁跨文件系统 | 不适用 | — | 按 D8 划在范围外，本地盘与 bind mount 语义已够 |
| HTTP 边界 | 已覆盖 | — | 状态码映射、`req_id` 唯一性、超限体的读数都在 `internal/raft/http_rpc_test.go`（`3.2` §3） |
| 压缩与快照 | 不适用 | — | 实现与验收归 `docs/5`，不进本矩阵 |
| 已有模块回归 | 不适用 | — | 本模块是仓库第一个模块；从 M3 起每次合并跑全量 `go test -race ./...`，防新代码改坏旧用例 |
