写路径保持 Raft 日志复制与提交语义不变。
读路径提供两种线性一致读法：Lease Read 与 ReadIndex。
共同要求是：读请求不得返回未提交、未应用或旧领导权下的状态；无法确认领导权或无法等待应用到位时返回失败，不得降级为本地旧数据读取。

### 共同不变量
1. 读返回前，要么处于多数派确认建立的有效租约内，要么本次读已完成多数派领导权确认；确认、租约和读索引必须绑定同一任期。
2. 读请求到达时记录当时已提交索引作为下界；最终读索引不得小于该下界，本地状态机必须至少应用到读索引。确认或续期过程中提交索引继续推进时，可使用更新的读索引，但不得使用更旧的。
3. 发现更高任期立即停止读服务，旧租约和未完成确认作废；不得跨任期复用确认结果或租约。
4. 租约不持久化，重启后必须重新确认；恢复后的读请求不得沿用旧租约。
5. 租约使用单调时间并扣除时钟漂移余量；选举超时、心跳间隔和漂移余量配置必须保证租约有效期计算为正且覆盖最坏时钟偏差。
6. 客户端重试视为新的读请求，必须重新执行对应读法的领导权条件，不得复用上一次确认结果、租约判断或读索引。
7. 多个读可共享应用进度通知和批量确认，但每个读仍受自己的读索引下界约束；共享不得让后到读请求复用其到达前已完成的旧确认。

### Lease Read
Leader 发送心跳前记录单调时间戳作为租约起点，但租约只有在同一轮、同一任期、多数派成功响应且未发现更高任期后才成立；部分成功、跨轮或跨任期响应不得拼凑为多数派确认。确认成功后，租约截止时间按“起点 + 选举超时时间 - 时钟漂移余量”计算；若确认完成时该截止时间已早于当前时间，本轮租约不生效。

读请求到达时先记录当前已提交索引作为下界
。若租约有效且任期一致，则以当前已提交索引作为读索引，等待本地状态机应用到位后本地读取，不需要逐读进行多数派往返。
等待应用跨越租约截止本身不自动产生陈旧读，但读索引下界不得因此放宽；若实现要求返回时租约仍有效，则必须在截止前完成返回或重新确认，否则读失败。

若租约无效，则重新进行多数派领导权确认并续期；续期成功后必须以续期确认时刻的已提交索引刷新读索引，且不小于读请求到达时的下界，不能沿用旧下界作为最终读索引上限。
续期失败或超时则读失败。若剩余租约不足以覆盖确认、等待应用和返回的保守估计，应直接重新确认或失败。租约有效期内多个读请求可共享租约。

任期变化、发现更高任期、主动退位、失去多数派连通能力或重启，均立即使租约失效；
失效后已捕获但尚未返回的读请求按基线策略失败或重新确认，不得沿用旧租约继续本地读。

### ReadIndex
每次读请求逻辑上都需要一次当前任期下的多数派领导权确认。
确认成功后，以确认时刻的已提交索引作为读索引，且不得小于读请求到达时记录的下界，等待本地状态机应用到位后读取。
确认失败、发现更高任期、确认成功但返回前发现更高任期、等待应用超时或期间领导权变化，读请求失败。

允许合并优化：只有同一轮确认发起前已到达的读请求可共享该轮确认结果和读索引；
确认发起后到达的读请求必须等待下一轮确认，不得复用旧确认。
合并只减少往返，不改变每个读的领导权合法性和读索引下界。

### 选择与异常
Lease Read 延迟低，依赖时钟和选举超时配置；
ReadIndex 每次读需多数派确认，依赖更弱。 租约失效时可按配置回退到 ReadIndex，但必须执行完整多数派确认和读索引确定流程，不得复用旧租约、旧确认或旧读索引。
网络分区、慢多数派、任期切换、应用滞后、重启等情况下，均以读失败优先，不返回陈旧或未应用状态。
节点关闭、退位或进入降级状态时，未完成读请求按失败处理。
若时钟与超时配置无法保证租约有效期安全，Lease Read 不得启用或必须回退到 ReadIndex。
