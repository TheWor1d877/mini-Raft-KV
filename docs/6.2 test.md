# 6.2 成员变更与 Learner 测试说明

## 1. 测试范围与环境

测试范围：`6.1` 描述的配置条目编码、追加即生效、投票集合与多数派、learner 的行为约束、降级与提升入口、Leader 自降、超时自动降级，以及它们与日志截断、启动恢复、快照、读确认轮的接缝。

分层沿用 `3.2` 的四层：

| 层 | 跑法 | 特点 |
|:---|:---|:---|
| 单元 | `go test ./internal/raft`，内存 transport + `t.TempDir()` | 零 `sleep`，按 `Tick()` 次数推进时间（D16） |
| 集成 | 5 个 `Node` 共用一个内存 transport，跑变更与降级 | 真文件、真 fsync |
| 进程级 | 测试自己 `exec` 起 5 个 `cmd/miniraft-node`，用 HTTP 提交变更 | 只在回归与 M18 跑，`-short` 跳过 |
| 契约 | 两条新 HTTP 路径的字段、状态码与错误码 | 覆盖 400／409／503 三档 |

环境与依赖：Linux 本地盘，Go 1.22 以上，第三方依赖仍是 `go.uber.org/zap`。`go test ./...` 不依赖 docker、不依赖 etcd。

工作目录 `/home/howardhe/Project/mini-Raft`。

## 5. 覆盖缺口与补充计划

| 缺口 | 现状 | 影响 | 处理办法 |
|:---|:---|:---|:---|
| 真实的 5 分钟 | 用例把阈值换成 tick 数，脚本用 3000ms 跑一遍 | 只证明计时链路能触发，不证明 300000ms 这一档的抖动 | 人工跑一次 `scripts/demote_lagging.sh 2000 300000`，读数进 `docs/0`，这一档不进门禁 |
| 地址表变更 | 不做，`-peers` 静态（D37） | 扩容与缩容要改所有节点并重启，重启期间视图用全表兜底 | 与 etcd 的差异写进 doc 8；本模块不补 |
| joint consensus | 不做，一次一条变更（D38） | 变更期间的第二个请求回 409；连续两次变更要多等一轮提交 | 与 etcd 的行为差异归 doc 8 |
| learner 的追赶速度 | 补发快照的速度在 `5.2` 有读数，learner 这一档没有单独量 | 降级之后 learner 仍按普通成员复制，速度与 `3.1` 的复制路径相同 | `demote_lagging.sh` 记降级后 `matchIndex` 与 `commitIndex` 的差值，读数进 `docs/0` |
| 自动降级与网络分区叠加 | 不做 | 分区里的成员也会被判落后，5 分钟后被降级，恢复分区后要手动提升 | 归 doc 7 的注入矩阵 |
| 降级到 1 个 voter | 用例只到 2 个 voter | 只剩 Leader 自己时写不需要复制，也没有容错 | 由 `cmd/miniraft-kv` 的单节点档覆盖，与降级路径无关 |
| 视图不一致窗口的时长 | 只在内存集成里断言不出现双 Leader | 启动早期每个节点的默认集合都是全表，收敛前的窗口没有读数 | 进程级用例记下第一次 `membership applied from wal` 与启动的间隔，读数进 `docs/0` |
