# 4.2 Raft 一致性读测试说明

## 1. 测试范围与环境

测试范围：`4.1` 描述的 `read.go`（租约、确认轮、读队列、等待应用、时钟注入位）、`append.go` 的计票分支、`rpc.go` 的 `/get` 分派、`config.go` 的三个新开关与租约安全窗校验，以及这三者与 doc 3 已交付路径的接缝。日志压缩与快照（doc 5）、故障注入矩阵与时钟跳变（doc 6）、etcd 对拍与 toxc 的 `linearizable` 报告（doc 7）不在测试范围内。

分层：

| 层 | 跑法 | 特点 |
|:---|:---|:---|
| 单元 | `go test ./internal/raft -run 'Read\|Lease'`，假时钟 + 内存 transport | 零 `sleep`；租约长度由用例拨计数器推进（D16、D26） |
| 集成 | 5 个 `Node` 挂同一个内存 transport，读与选举、复制交织 | 真文件、真 fsync；等待应用那一格靠真 `Flush` 兑现 |
| 进程级 | 测试自己 `exec` 起 5 个 `cmd/miniraft-node`，发真 HTTP，`kill -9` Leader 期间持续读 | 只在回归与 M14 跑，`-short` 跳过 |
| 契约 | `/get` 的六键、503 的五个键、`append-entries` 的 7 个必填项 | 覆盖 `local` 与租约读、确认轮读三种形状到状态码的映射 |
| 数据 | `scripts/bench_read_modes.sh` 三档读延迟 | 单进程 keep-alive 客户端，与 `bench_single_vs_raft.sh` 同一套计时口径 |

环境与依赖：Linux 本地盘，Go 1.22 以上，第三方依赖仍是 `go.uber.org/zap`，日志断言用 `zaptest/observer`。`go test ./...` 在本地跑完，用不到 docker 与 etcd。

`2.2` 与 `3.2` 的口径不变：覆盖结论按里程碑同步维护，一格写「缺失」就是没跑过。

## 3. 逐文件说明

| 文件 | 被测对象 | 关键断言 | 覆盖场景 |
|:---|:---|:---|:---|
| `read_test.go`（新增） | `read.go`（D24~D28，`4.1` §7、§8） | 假时钟下：广播发起前取租约起点，过半时窗口仍剩 40ms 则 `lease granted` 与 `lease_remaining_ms` 对得上；把时钟拨过 `T - clock-drift` 再结算则 `lease rejected`，`lease_remaining_ms` 为负；租约命中的一次读发出的 AppendEntries 条数为 0（夹具的计数器）；剩余租约小于 `-read-timeout-ms` 时重新发一轮确认，不直接返回读数。等待门限：`commitIndex` 已推进、`lastApplied` 落后 30 条时，这一条读排进 `applyWaiters`，`finishApply` 兑现之后才拿到值，返回的 `read_index` 等于 `max(结算时的 commitIndex, 到达时的下界)`；结算那一轮落在日志里的 `read_index` 是同一个数。读索引下界单独一格：把提交游标拨回到比到达时的下界更旧的位置，结算给出的读索引与日志里的 `read_index` 仍取那条下界，不给更旧的数。合并窗口：一条读在轮次快照之后到达，本轮成员表不含它，`read round sent` 的 `reads` 是快照里的条数，它自己走下一轮。跨轮回执：注入一条编号错位的 `success`，计票数不变并打 `stale read round dropped`；第 3 票收到即结算，之后两票不改动已经定下的 `read_index`。失效四个入口：更高任期、`becomeFollower`、`Close`、重启（`NewNode` 之后 `LeaseRemaining() <= 0`）之后，旧租约上的读一律拿 `ErrNotLeader` 或 `ErrCanceled`，`kv.Get` 一次都不调（D24） | 租约、读索引、合并、失效 |
| `append_test.go`（扩展） | `append.go` 的计票分支（D25） | `appendOnce` 在 `activeRound` 存在时把 `readRound` 填成本轮编号，队列为空时填 0；带条目的同任期 `success` 回执同样计票（不要求空数组）；`reply.ReadRound == 0` 的回执不进读路径的计数，仍然照常推进 `matchIndex`／`nextIndex`；`acks` 到 `N/2+1` 立即结算，`read round settled` 的 `acks` 是 3 | 确认轮、复制游标互不干扰 |
| `cluster_test.go`（扩展） | 5 节点内存集群的读与选举交织 | Leader 上写一条、推 4 轮后，`lease` 与 `readindex` 两种模式在 Leader 上读到同一个值且 `read_index` 不小于写返回的 `index`；`kill`（`closeNode`）Leader 后剩余节点重选主，新 Leader 的第一个线性读走一轮确认才返回，`ReadRound` 从 1 起；`partition` 成 2/3 两半后，2 的那半即使有节点自认 Leader，线性读全部失败（确认轮凑不齐 3 票），`consistency=local` 仍回 200 并带 `stale:true`（不变式 6） | 5 节点集群、分区、失败不降级 |
| `http_rpc_test.go`（扩展） | `rpc.go` 的 `/get` 与两个 RPC 的新字段（D24、D25、D28、D30） | `/get` 成功响应固定六键 `key`／`value`／`req_id`／`read_index`／`term`／`stale`；`consistency` 缺失即默认档，非 Leader 上回 503 `not_leader`，五个键与 `/put` 那格逐键相同；`consistency=local` 在 Follower 上 200 且 `read_index` 为 0、`stale` 为 `true`；`consistency=bogus` 与非 GET 方法各自 400 与 405；`append-entries` 缺 `readRound` 回 400，带 `"readRound":0` 通过；Follower 的回执把编号原样带回；`-read-timeout-ms` 压到 1ms 时读回 500 `canceled`，`applyWaiters` 里那一格随之摘掉，不留唤醒不了的等待 | 契约、超时 |
| `state_test.go`（扩展） | `config.go` 的三个开关与 `Validate()` 的新增三条（D29） | `-read-mode` 不在 `lease`／`readindex` 里报错；`-clock-drift-ms < 0`、`-read-timeout-ms <= 0` 各自报错；`lease` 档配 `-election-timeout-ms 400`（5 节点、RPC 超时 100ms）报租约窗口不够，`readindex` 档同一份配置通过；`readindex` 档配 `-read-timeout-ms 300` 报「读超时撑不过一轮广播」；`NewNodeLogger` 那条链不变 | 配置、租约安全窗 |
| `commit_test.go`（扩展一格） | apply 与读等待的接缝（`4.1` §8 第一条、D27） | Flush 失败的那一批里 `lastApplied` 不动，落在该批上的线性读不返回成功，`read wait timed out` 带 `read_index`／`last_applied`／`commit_index` 三个游标；恢复补 apply 之后同一个读请求立刻成功 | 等待门限、失效下游 |
| `cluster_fixture_test.go`（扩展） | 假时钟与读路径夹具（D26） | 假时钟每调一次 `Tick()` 前进 `-tick-ms`，用例可单独拨快；夹具记录每条 AppendEntries 的 `readRound`，能按轮次注入回执；`now` 注入位只在 `read.go` 被调用，`node.go`、`append.go`、`commit.go`、`vote.go` 四个文件里 `time.Now()` 与 `time.Since` 一次都不出现，这条用一条 grep 断言检查（`4.1` §3 的禁止项） | 测试装置 |
| `cluster_process_test.go`（扩展） | 真进程下的读与重选主 | `-short` 跳过；`kill -9` Leader 期间对旧 Leader 地址持续发默认 `/get`，结果只有三种：200 且值等于最后一条确认写、503 `not_leader`、500 `canceled`；出现 200 时 `read_index` 大于等于该值的日志 index，且整个窗口内一次都不出现「200 且值旧于最后确认」；`consistency=local` 在同一窗口里能读到旧值，这一格是 `docs/1`「读到旧值」负载的装置证据 | 进程级、线性一致 |

## 5. 覆盖缺口与补充计划

| 缺口 | 现状 | 影响 | 处理办法 |
|:---|:---|:---|:---|
| 真时钟跳变 | 假时钟能拨，NTP 步进与进程冻结造不出来 | D26 那条「单调时钟的前提是进程不暂停」只有推演 | 归 doc 6 的注入矩阵；本轮只把 `-clock-drift-ms` 留作可调参数 |
| 线性一致的形式化检查 | 用例做的是行为断言，没有历史序列检查 | 线性一致只能给行为断言，给不出「无违规」的结论 | toxc 的 `linearizable` 报告归 doc 6 与 doc 7，`docs/1` 的结项清单那一格在报告出来之前按未完成写 |
| 租约命中率的真实读数 | 默认配置的租约余量只有 50ms（`4.1` §6 第 2 条、D29 的校验对象） | 命中率为 0 是合法结果，不代表实现正确 | `bench_read_modes.sh` 每档同时统计 `lease granted`／`lease rejected` 两条日志的计数，`-election-timeout-ms` 1000ms 再跑一档 |
| 单条确认轮的分跳耗时 | 一轮 4 跳串行，日志只有 `round_cost_ms` 一个总数 | 读延迟读不出「哪一跳慢」 | 与 `3.2` §5 那条「单条 RPC 耗时没进日志」是同一件事，仍然没有分跳读数；doc 7 对拍时这一格按一轮的总耗时读 |
| Follower 转发 | 本模块不做，非 Leader 一律 503 | 读流量的可用性集中在 Leader | 与 etcd 的行为差异写进 doc 7，D24 的理由栏 |
| 读的并发压力 | 用例最多 5 个并发读者，没有 100 连接的读数 | 锁竞争在读路径上的形状没有读数 | `bench_read_modes.sh` 先跑单连接三档，多连接的锁竞争开销由 doc 6 的负载矩阵去量 |

## 6. 与里程碑的对应

里程碑的任务拆分与先后顺序写在 `4.4`。

M14 收 `read_test.go`（新增）、`append_test.go`／`cluster_test.go`／`http_rpc_test.go`／`state_test.go`／`commit_test.go`／`cluster_fixture_test.go`／`cluster_process_test.go` 七个文件的扩展格，收 `scripts/bench_read_modes.sh` 的三档读数。doc 2 与 doc 3 的既有套件在 M14 之后仍要逐格通过，raft 侧那 17 处 `/get` 调用点按 D24 补 `consistency=local`，`internal/kvstore` 那 12 处不动（D30）。

门禁每个里程碑跑一次：`gofmt -l internal cmd`、`go vet ./...`、`go test ./...`、`go test -race ./...`。

变异自证按轻量口径，每条判据各造一个变异，跑完还原：

| 变异 | 预期被哪个用例杀掉 | 里程碑 |
|:---|:---|:---|
| 把 `4.1` §7 的 `startNS` 从广播发起前挪到过半回执那一刻取 | `read_test.go` 的 `TestReadLeaseRejectedWhenTheWindowIsBurned` | M14 |
| 计票不判 `readRound` 编号，`success=true` 就算一票（跨轮拼接） | `read_test.go` 的 `TestReadDropsRepliesFromAnotherRound` | M14 |
| 结算时 `readIndex` 直接取当前 `commitIndex`，不与到达时的下界取大 | `read_test.go` 的 `TestReadIndexNeverOlderThanTheArrivalBound` | M14 |
| `becomeFollower` 不清空租约与在途轮次 | `read_test.go` 的 `TestReadLeaseInvalidationEntries` | M14 |
| 合并窗口放开：登记在途的读都算进本轮成员 | `read_test.go` 的 `TestReadRoundKeepsLateArrivalsForTheNextRound` | M14 |
| 读不等 `lastApplied`，拿到 `readIndex` 就直接 `kv.Get`（D27 的门限删掉） | `read_test.go` 的 `TestReadParksUntilTheLaggingApplyCatchesUp`、`commit_test.go` 的 `TestLinearReadWaitsOnTheApplyThatFailedToFlush` | M14 |
| 非 Leader 的线性读兜底成本地读（把 503 换成 200 带旧值） | `http_rpc_test.go` 的 `TestGetContractTwoConsistencyModes`、`cluster_process_test.go` 的 `TestReelectionWindowLinearReadResults` | M14 |
| `appendFields` 里删掉 `readRound` 的必填检查 | `http_rpc_test.go` 的 `TestAppendEntriesRequiresReadRound` | M14 |

8 条变异各造一遍：前 7 条与最后一条的目标用例当场变红，`becomeFollower` 那一条是用例挂死——等待格永远不兑现——被 `go test -timeout` 杀掉的。还原后 `internal/raft/*.go` 的 md5 与造变异之前逐个相同。下界那格的用例是本轮补的：跑第一遍时这条变异谁也没杀掉，结算里「读索引与成员下界取大」那处当时没有任何断言看着它。
