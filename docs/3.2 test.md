# 3.2 Raft 核心逻辑测试说明

## 1. 测试范围与环境

测试范围：`3.1` 描述的 state、日志（wal）、vote、election、append、commit、read、rpc 九个内部件，加上 `cmd/miniraft-node` 与 `cmd/miniraft-kv` 两个进程入口。日志压缩与快照（doc 5）、故障注入矩阵（doc 6）、etcd 对拍（doc 7）不在测试范围内。

分层：

| 层 | 跑法 | 特点 |
|:---|:---|:---|
| 单元 | `go test ./internal/raft`，内存 transport + `t.TempDir()` | 零 `sleep`，按 `Tick()` 次数推进时间（D16） |
| 集成 | 5 个 `Node` 共用一个内存 transport 跑选举与复制 | 真文件、真 fsync，耗时集中在 IO |
| 进程级 | 测试自己 `exec` 起 5 个 `cmd/miniraft-node`，发真 HTTP、`kill -9` Leader | 只在回归与 M13 跑，`-short` 跳过 |
| 契约 | 两个 RPC 路径与 `/put`、`/get` 的 JSON 字段断言 | 覆盖 term 比较分支到状态码的映射 |

环境与依赖：Linux 本地盘，Go 1.22 以上，第三方依赖仍是 `go.uber.org/zap`，日志断言用 `zaptest/observer`。`go test ./...` 不依赖 docker、不依赖 etcd。

`2.2` 的口径不变：覆盖结论按里程碑同步维护，一格写「缺失」就是没跑过。

## 6. 与里程碑的对应
