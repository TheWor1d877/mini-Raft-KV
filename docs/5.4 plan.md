# 5.4 日志快照施工计划

任务编号接 `4.4` 的 T30 排到 T31；判据一律写在 `5.1`、`5.2`、`5.3`。

## 0. 总览

| 里程碑 | 名称 | 交付物 | 收口判据 | 预估机时 |
|:---|:---|:---|:---|:---|
| M15 | 快照与压缩 | `internal/raft/snapshot.go`、`compact.go`、`install.go`、`wal.go` 的基线 index、`node.go` 的启动恢复顺序、`internal/kvstore` 的导出面，加三个新测试文件与五个文件的扩展格 | `5.1` §8 的八条不变式各有用例；`5.2` §6 表里 M15 那八条变异能杀 | 两天 |

顺序固定：T31 先把状态机导出面与快照文件格式立起来，T32 才能改启动恢复顺序，T33 的日志前缀删除依赖 T32 的基线 index，T34 的补发快照依赖 T33 的删除边界。M15 内部不合并。

每个里程碑的放行门禁固定四条，跑完才进下一个：

```bash
gofmt -l internal cmd && go vet ./... && go test ./... && go test -race ./...
```

## M15 快照与压缩（T31~T34）

| 步骤 | 做什么 | 落点 | 完成判据 |
|:---|:---|:---|:---|
| T31.1 | kvstore 导出面：`type Entry struct { Key, Value string }`、`Snapshot() []Entry` 导出全量键值、`Restore(entries []Entry)` 整体替换 map；导出走 `KV` 自己的读写锁 | `internal/kvstore/kv.go` | `Snapshot()` 的结果顺序稳定；`Restore()` 之后被替换掉的键读不到 |
| T31.2 | 快照文件的编码与写入：`op 1B(=0x20)｜keylen 4B｜key｜vallen 4B｜value`，帧头调 `kvstore.EncodeFrame`／`DecodeFrame`／`CheckFrame`；文件是 8B magic + 4B 条目数 + 帧序列；写临时名 → Sync → 改名 → Sync 父目录 | `internal/raft/snapshot.go` | 逐字节布局断言；两个目录互读判坏（D34） |
| T31.3 | 元数据指针 `raft/snapshot/current.json`：字段 `snapshotIndex`／`snapshotTerm`／`entries`／`bytes`／`checksum`，写入走临时名 → Sync → rename → Sync 父目录；读的时候缺字段、半行 JSON、文件不存在三种情况按「没有快照」起 | 同上 | D31；指针坏了只丢指针，state 游标不受影响 |
| T31.4 | `snapshot_test.go`：格式、提交顺序、指针的三种坏输入、`*.tmp` 与孤儿快照文件的清理 | `internal/raft/snapshot_test.go` | `5.2` §3 的 `snapshot_test.go` 行逐条对上 |
| T32.1 | 日志视图的基线：`wal` 结构体加 `baseIndex` 与 `baseTerm`，`entryAt` 与 `entriesFrom` 按 `index - baseIndex` 取下标，删前缀时 `baseTerm` 跟着挪；恢复扫描在有快照时要求日志覆盖 `snapshotIndex+1` 起的连续区间，第一条晚于它判 `ErrStateMismatch`、早于它的残留条目跳过，没有快照时第一条必须是 1 | `internal/raft/wal.go` | `5.1` §5 的基线口径；index 小于基线取不到条目 |
| T32.2 | 启动恢复顺序改成四步：读指针与快照 → 读快照重建状态机 → 回放 `index > snapshotIndex` 的条目直到 `lastApplied` → 补 apply `(lastApplied, commitIndex]`；指针或快照文件缺失、损坏时按没有快照起 | `internal/raft/node.go`、`internal/raft/snapshot.go` | `5.1` §7 启动恢复；快照文件损坏且日志前缀已删时启动失败，不静默起空 map |
| T32.3 | `wal_test.go` 与 `recovery_test.go` 的扩展格：基线 index、扫描首条的口径、恢复时回放起点 | `internal/raft/wal_test.go`、`internal/raft/recovery_test.go` | `5.2` §3 两行的扩展格逐条对上 |
| T33.1 | `safeIndex`：Leader 取全部成员 `matchIndex` 的最小值（自己算一个成员），Follower 取本地 `commitIndex`；豁免中的成员不参与计算 | `internal/raft/compact.go` | `5.1` §7 删除边界；豁免发生时打 `snapshot exemption applied` |
| T33.2 | 删除边界 `min(snapshotIndex, safeIndex)` 与 `dropLogPrefix(index)`：整段文件删掉、保留的那一段截到它的帧起点、视图的 `baseIndex` 前移、term 到首末 index 的两个映射重建 | `internal/raft/compact.go`、`internal/raft/wal.go` | `5.2` §3 的三种落点；删除后 `entryAt` 按新基线取下标 |
| T33.3 | 触发判定：`Tick()` 里按 `-snapshot-entries`、`-snapshot-bytes` 与 `-snapshot-min-interval-ms` 判定；快照状态位挡住并发触发；快照点被 `lastApplied` 卡住时打 `snapshot blocked by apply lag` | `internal/raft/compact.go`、`internal/raft/node.go` | 不变式 4；两个阈值都为 0 时自动触发全关 |
| T33.4 | `compact_test.go`：边界、豁免、三种落点、触发条件、并发触发 | `internal/raft/compact_test.go` | `5.2` §3 的 `compact_test.go` 行逐条对上 |
| T34.1 | 两条 HTTP 路径与 transport 方法：`POST /raft/snapshot`、`POST /raft/install-snapshot?index=&term=`（请求体是快照文件原始字节）；`statusFor` 加 `ErrStateMismatch` → 409 `state_mismatch` | `internal/raft/rpc.go`、`internal/raft/errors.go` | `5.1` §4 形状表；D32 |
| T34.2 | 接收路径五步：校验 magic 与条目数与 crc32c → index 不够大时直接成功 → 锁外解码、锁内整体替换状态机 → 推进 `lastApplied` 与 `commitIndex` 并写 state 游标 → 写本地快照文件与指针、删本地日志前缀 | `internal/raft/install.go` | 不变式 3、7、8；坏快照返回 `ErrCorruptRecord` |
| T34.3 | Leader 侧补发：复制游标落到自己日志基线以下时先发一次 `POST /raft/install-snapshot`，再继续复制 | `internal/raft/append.go`、`internal/raft/compact.go` | 落后成员靠快照追平，不靠日志回退 |
| T34.4 | `install_test.go` 与 `http_rpc_test.go`、`cluster_process_test.go` 的扩展格 | `internal/raft/install_test.go`、`internal/raft/http_rpc_test.go`、`internal/raft/cluster_process_test.go` | `5.2` §3 三行的扩展格逐条对上 |

## 范围外

成员配置变更与 learner 降级归 doc 6，`5.3` D33 已定本期只做豁免。快照文件不做压缩编码，快照文件按明文键值存。补发快照不分块、不做断点续传，一个快照文件一次发完。快照不预生成，也不做定期备份。网络分区与时钟跳变的注入矩阵、etcd 对拍归 doc 7 与 doc 8。
