# miniRaft 定位介绍

## 定位

给 TrainCache 的存储层选型提供论证，不是一道功能题。

TrainCache 的元数据、就绪度进度、协调状态都放在 etcd 上，「为什么不自研一套 Raft」目前只有结论没有依据。这个项目做出一个能跑的 5 节点 Raft KV，把自研要付的代价量出来，再回答这个问题。

目标是把一致性从背出来的知识点变成能讲清楚的东西：选举怎么做、日志怎么复制、快照怎么裁、崩溃后怎么恢复，每一项都能对着自己写的代码和跑出来的数据说。

## 范围

做：
- 5 节点集群，对外暴露 Put/Get 接口
- 选举、日志复制、快照、崩溃恢复
- 故障注入：`kill -9`、网络分区、时钟跳变
- 与 etcd 跑同一串操作做行为对拍

对拍的负载：单键 Put/Get、批量写、读到旧值、客户端重试、leader 切换时的写。

对拍的参照是 etcd 的行为：同一串操作打给 etcd，记下它返回什么，和 mini-Raft 的结果比。etcd 的源码只作参考，不作为对照对象。

不做（这两项要求能在白板上讲清楚，不写代码）：
- membership 变更
- Pre-Vote

## 项目价值

MIT 6.824 里人手一个，实现本身的差异化几乎为零。简历上永远不要把它排在第一位。

弹药全在三处：工程细节（为什么这么切状态、锁放在哪、超时怎么定）、实验设计（故障注入怎么排布、指标看什么）、以及和 etcd 的对拍（同一个操作序列，两边行为哪里一致、哪里不一样、差异从哪来）。

## 落脚点

结项时能对一句话负责：TrainCache 为什么用 etcd，而不是自研 Raft 实现。产出物不是一个能上线的库。

### 结论的形式

一句话结论后面挂三类证据，缺任何一类就写成未完成：

- 自研付掉的代价：代码量、时间、坑的条数与根因、需要长期维护的边界条件
- etcd 白给的东西：一致读、租约、条件写、部署与生态
- TrainCache 的能力清单：实际用到 etcd 哪几项、哪几项用不到

用不到的项越多，「自研更划算」的空间看起来越大，代价账要跟着算细。

### 结项清单

| 项         | 产出                                                               | 完成判据                                                                                                                |
|:-----------|:-------------------------------------------------------------------|:------------------------------------------------------------------------------------------------------------------------|
| 一致性检查 | toxc `linearizable` 报告，加打戳寄存器自检结果                     | 无故障、`kill -9`、网络分区各跑一轮，三份报告原文存档；违规逐条开 issue；没修完的在结论里写「一致性未验证通过」，不含糊 |
| 行为对拍   | 五种负载 × 两边行为的对照表                                        | 每格写清 etcd 返回什么、mini-Raft 返回什么、差异来自哪一层；没跑的格标未跑                                              |
| 故障注入   | 每种故障的恢复数据                                                 | `kill -9`、网络分区、时钟跳变各记录：重选主耗时、在途写是否丢、客户端看到的错误；每个数字有原始日志可查                 |
| 成本账     | 自研代价汇总                                                       | 行数、耗时、issue 数逐条指向具体文件或 issue，能复算                                                                    |
| 白板项     | membership 变更与 Pre-Vote 的讲稿                                  | 不看资料讲完，能答两个追问                                                                                              |
| 复盘笔记   | `/home/howardhe/Project/Note/mini-Raft/` 下的结项论证与机制笔记    | 每条说法能指到代码位置或实验产物                                                                                        |

### 阴性结论

跑不出无违规的一致性报告，或对拍出现解释不了的差异时，结论按实际写：卡在哪一层、下一步查什么。差异本身算弹药，和 TrainCache 允许阴性结论的口径一致。

### 收尾

1. 一句话结论连同三类证据写进 README。
2. GitHub issues 全部关闭，保留的写明原因。
3. 简历里这条的写法与排位一并定下来。
