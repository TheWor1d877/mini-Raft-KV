# 5.3 日志快照决策记录

编号接 `4.3` 的 D30 往后排。

## D31 元数据指针独立成 `raft/snapshot/current.json`

- 背景：快照提交之后要有一处记录「当前有效的快照是哪一份」，崩溃恢复以这个指针为准。
- 备选：指针写进 `raft/state` 小文件；指针独立成文件。
- 结论：独立文件 `raft/snapshot/current.json`，字段 `snapshotIndex`、`snapshotTerm`、`entries`、`bytes`、`checksum`，写入走临时名 → Sync → rename → Sync 父目录。
- 理由：`raft/state` 每批 apply 重写一次，里面装的是四个共识标量。快照指针只在快照提交那一刻变，两者的更新频率差三个数量级。把指针混进 state 会让每次 apply 都拖着快照信息一起改，而 `state` 的字段白名单与一致性检查都是按四个标量写的。独立文件还有一个好处：指针坏了可以只丢指针，state 的两个游标不受影响。
- 影响：`raft/snapshot/` 目录与指针文件新增；启动流程多一步「读指针，字段缺失或文件不存在按没有快照起」。`raft/state` 仍是四个标量，字段与不变式不变。
- 验证：指针文件被写成半截 JSON 时启动按没有快照起；快照文件缺失时同样；指针与快照文件对不上（checksum 不符）时判坏并按没有快照处理。

## D32 补发快照走 HTTP，不用 gRPC

- 背景：落后成员的日志前缀已经被 Leader 删掉，复制请求带不齐条目时，Leader 要把整份快照发给该成员。
- 备选：新增一条 gRPC 接口；用现成的 HTTP 通道发二进制。
- 结论：新增 `POST /raft/install-snapshot?index=&term=`，请求体是快照文件的原始字节，响应是 JSON。与 `/put`、`/get`、`/raft/append-entries` 共用同一个监听端口。
- 理由：项目现有两条节点间 RPC 都是 JSON over HTTP，再引一套 gRPC 要多一份代码生成、一套端口、一套错误映射，而这条 RPC 的负载是二进制文件本身，不需要 gRPC 的流式与代码生成能力。玩具级项目多一套协议栈的收益是零。
- 影响：`rpc.go` 增加一条路由与一个 transport 方法；快照传输没有分块与断点续传，一个快照文件一次发完，文件大小的上限就是请求体的上限。
- 验证：5 进程用例里让一个成员落后到日志前缀被删，发起一次复制后它能读回快照点之后的写。

## D33 豁免规则本期实现，learner 降级与成员配置归 doc 6

- 背景：doc 5 基线把「落后成员豁免出 `safeIndex` 的计算」与「超过 5 分钟降级为 learner」写在一处，两件事的依赖不同。
- 备选：两件都做；两件都不做；按依赖拆开。
- 结论：豁免规则本期实现，它依赖的是补发快照（D32）。降级为 learner 与成员配置变更归 doc 6。
- 理由：豁免只改 Leader 算删除边界时看哪些成员，不改 quorum 的计算，Leader 单方面就能定，代价是那个成员要靠快照补齐。降级为 learner 改的是 quorum 的大小，成员配置在 Raft 里是一条日志条目，各节点要靠复制这条条目达成一致；`docs/1` 把 membership 变更列为不写代码，本期没有成员变更这条路径。
- 影响：`5.1` §7 写豁免的判定与报警，doc 6 写降级与恢复的规则与实现。
- 验证：豁免发生时日志里出现 `snapshot exemption applied`；被豁免的成员最终通过 `POST /raft/install-snapshot` 追平。

## D34 快照记录用 `op=0x20`

- 背景：快照文件里的每条记录要有一个 op 值，与 raft 日志条目的 op 值区分开。
- 备选：`0x00`；`0x11`；`0x20`。
- 结论：快照记录的 op 取 `0x20`，与 raft 日志条目的 `0x10` 分属两族。
- 理由：`0x00` 在帧层与「空、未设置」贴近，`kvstore.DecodeEntry` 也把非 `0x01` 的 op 一律判坏记录，取 0 容易与别的判坏原因混在一起。`0x11` 与 `0x10` 只差最低位，语义上属于同一族，而 raft 日志族自己还要留位给 no-op 条目与将来的成员配置条目。快照是独立的一族，取 `0x20` 之后两个目录互读都判坏记录，沿用 `wal.go` 已有的做法。
- 影响：快照文件的 payload 首字节固定 `0x20`；解码时遇到别的 op 判坏记录。
- 验证：把一个 raft 日志段当成快照文件读，解码报 op 非法；把快照文件当成日志段扫，扫描报 op 非法。
